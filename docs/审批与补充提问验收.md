# 审批与补充提问验收

本批为第二阶段交互功能，沿用 Hermes 0.23.0 官方 Runs API。现有紫色主题、工具折叠、图片附件、会话发送恢复和工作区其他改动保持兼容。

## 功能与接口

- 审批展示 Hermes 提供的说明、脱敏命令、可选文件修改内容，只提供“允许一次”和“拒绝”。不提供会话级、永久或批量授权，不自动审批。
- 补充提问展示问题、单选或多选选项以及自由回答，回答后解除原工具等待，继续同一次运行，不创建另一条推理请求。
- 待处理请求以官方 `pending_controls` 为准，携带 `run_id`、`prompt_id`、`execution_generation`。SSE 用于提示更新，活动运行每三秒补查一次快照，兼容 SSE 未广播提问的情况。
- `POST /api/sessions/{id}/approval` 接收 `run_id`、`request_id`、`execution_generation`、`choice`，仅允许 `once` 或 `deny`。
- `POST /api/sessions/{id}/clarify` 接收相同身份字段及 `answer`，回答限制 16,384 个 Unicode 字符。接口要求登录和同源请求，只允许处理 Haven 自有登记中属于该会话的运行。
- 服务端先核对实时快照，再调用 `/v1/runs/{id}/approval` 或 `/clarify`。原生接口最终裁决并发、代次和请求身份，过期或被其他入口处理的请求返回 409，不回退到下一个请求。
- 回答草稿与提交不确定标记按账号、会话、运行、请求和代次隔离保存。刷新、切换会话、重新登录后核对原生状态，双击不会重复提交；响应丢失不会自动重试，须用户核对后再决定。
- 审批、提问和待确认状态只在展示及 Haven 浏览器草稿中处理，不修改历史消息，不写入审批回答副本到 Hermes 历史。

接口依据：[官方 API 文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server)，以及服务器安装版本的 `gateway/platforms/api_server_authority_runs.py`、`gateway/session_pending_controls.py`。

## 自动化与浏览器验证

后端验证有效回答、拒绝、非法参数、空白及超长回答、任意请求编号字符、外会话访问、错误类型、过期代次、批量和永久授权拒绝、未登录、跨来源、并发处理、Haven 重启及响应丢失不重试。前端验证身份投影、双击、草稿隔离和恢复、过期卡片、响应丢失核对后手动重试，以及 SSE 无提问事件时的轮询发现。

浏览器在独立本机 mock 和 Haven 数据目录中验证审批卡片、拒绝后运行结束、补充回答的选项与自由输入、刷新恢复、提交后继续原运行。390×844 手机视口下卡片和按钮可见，无横向溢出；完成后恢复原视口。

## 真实 Hermes 联调

`dev/live_controls.py` 启动服务器已安装的真实 Hermes 进程，使用独立 HOME、配置及数据库和确定性的本机模型桩。四种场景均通过：拒绝、允许一次、补充回答、多选回答。审批及提问等待中重启 Haven，恢复相同原生请求；每个请求并发提交四次，模型总共只有八次请求（每个场景工具前后各一次），工具等待未重复执行。

证据：`/var/lib/hermes-haven/acceptance/controls-01a1aece-v1/result.json`，该目录保留验收数据。

随后连接日常服务器的真实模型，所有发送只进入新建验收会话：

- 会话 `haven_696bd1425efb02ed7b1d2ed2b3706b26`。
